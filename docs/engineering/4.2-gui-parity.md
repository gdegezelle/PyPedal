# PyPedal 4.2 GUI parity matrix

Engineering inventory for the PySide6 desktop that replaced the
temporary CustomTkinter application. This file is not part of the user
manual and is not in MkDocs navigation.

PyPedal 4.2-E completed the source cutover. CustomTkinter is removed from
the runtime product. `pypedal`, `pypedal-gui`, and `python -m PyPedal`
launch `PyPedal.desktop`. `PyPedal.pyp_app` is a thin compatibility
launcher with no widgets.

## Former CustomTkinter features

| Feature | Former CTk implementation | Library API | Target PySide6 replacement | Parity | Status |
|---|---|---|---|---|---|
| Application launch | `pyp_app.main`, `python -m PyPedal`, `pypedal`, `pypedal-gui` | none (process entry) | `QApplication` / `QMainWindow` via `PyPedal.desktop`; `pyp_app` is a thin launcher | MUST | **replaced** |
| Open pedigree | `filedialog.askopenfilename` then `NewPedigree(options).load(progress=...)` | `NewPedigree.load` | Native File menu `Open…` (`QKeySequence.StandardKey.Open`); no in-window Open button or toolbar | MUST | **replaced** |
| pedformat | `CTkEntry` bound to `format_var`, default `asdxb`; empty falls back to `asd` | `kw["pedformat"]` | Same field on the open dialog; desktop default `asd` | MUST | **replaced** |
| Separator | `CTkEntry`, empty means space; `normalize_sepchar` | `kw["sepchar"]` | Same normalisation in application; desktop presents the field | MUST | **replaced** |
| Renumber option | `CTkCheckBox`, default on | `kw["renumber"]` | Same checkbox/toggle | MUST | **replaced** |
| Failed-load retention | `apply_pedigree_load` on the UI thread | none | `PedigreeSession` replaces only after success | MUST | **replaced** |
| Metadata | `pedigree.metadata.stringme()` into a text box | `PedigreeMetadata.stringme` | Read-only top-aligned inspector | MUST | **improved** |
| Animal listing | `_list_animals`, cap 500 rows | `ped.pedigree` / `NewAnimal` | Virtual `QAbstractTableModel` over `PedigreeTableSource` | IMPROVE | **improved** |
| Meuwissen–Luo inbreeding | `pyp_nrm.inbreeding(..., method="meu_luo", progress=...)` | `pyp_nrm.inbreeding` | Application job `run_inbreeding` (`output=False`, progress); cached result | MUST | **replaced** |
| Inbreeding summary | `_format_inbreeding` + 500-row preview | `InbreedingResult` | Structured summary plus full coefficient table | IMPROVE | **improved** |
| Lacy effective founders | `pyp_metrics.effective_founders_lacy` | `effective_founders_lacy` | Application job; typed result page | MUST | **replaced** |
| Inbreeding by year | Recomputes Meuwissen–Luo then averages locally | `animal.by` + existing `fx` | Group cached `InbreedingResult.fx` via `group_inbreeding_by_year` | IMPROVE | **improved** |
| About | `messagebox.showinfo` | `PyPedal.__version__` | Native About box | MUST | **replaced** |
| Busy state | Tk widget state | none | Disable Open and analyses while a job runs | MUST | **replaced** |
| Progress | Tk polling over `GuiProgressBridge` | `ProgressCallback` | Qt signal/slot; no cancel | MUST | **replaced** |

## Quiet load decision

`PedigreeOpenOptions` defaults to `messages="quiet"` and
`pedigree_summary=0`. The PySide6 desktop uses those application
defaults.

## Dependency direction

```
PyPedal.desktop
        ↓
PyPedal.application
        ↓
PyPedal scientific modules
```

Permanent prohibition: scientific modules importing application or
desktop. Application must not import PySide6, tkinter, or customtkinter.
Application objects must not hold Qt types. Desktop reaches science
through application adapters.

Application must never import `pyp_app`. `pyp_app` may import desktop
only inside `main()`.

## Post-4.2 desktop UX follow-ups

Relationship and Mating currently require **current (renumbered) animal
IDs**. That matches the scientific call identifiers.

A later desktop enhancement should let operators locate animals by:

- name
- original ID
- current animal ID

Names may not be unique. Original IDs are often what operators know.
Ambiguous matches must be disambiguated explicitly; the UI must not
silently pick the first duplicate name. A candidate presentation is
conceptually `<name> — original ID <x> — animal ID <y>`. This is **not**
implemented in 4.2. Scientific relationship/mating APIs stay unchanged.
