# PyPedal 4.2 GUI parity matrix

Engineering inventory for replacing the temporary CustomTkinter desktop
with a PySide6 application. This file is not part of the user manual and
is not in MkDocs navigation.

PyPedal 4.2-B adds `PyPedal.desktop`, a native PySide6 shell on top of
the 4.2-A `PyPedal.application` layer. CustomTkinter remains the
operational GUI for `pypedal`, `pypedal-gui`, and `python -m PyPedal`
until 4.2-E. Analysis run UI is 4.2-C.

Preferred 4.2-E compatibility option: keep `PyPedal.pyp_app` as a thin
launcher that delegates to `PyPedal.desktop`, containing no CustomTkinter,
no tkinter, and no legacy UI implementation. Removing that import path
requires explicit evidence that the break is acceptable. That cutover is
not implemented in B.

## Counts

- Current CTk features inventoried: **15**
- MUST retain/replace: **13** current features (launch through progress, excluding the two IMPROVE listings that still remain required capability)
- IMPROVE: animal listing, inbreeding summary, inbreeding-by-year (and several SHOULD items)

## Quiet load decision (4.2-A)

The CustomTkinter open path sets `messages="quiet"` and does **not** set
`pedigree_summary=0`. Because quiet already suppresses the verbose
metadata dump, that CTk behaviour is left unchanged.

`PedigreeOpenOptions` defaults to `messages="quiet"` **and**
`pedigree_summary=0`. The PySide6 desktop uses those application
defaults.

## Dependency direction

```
PyPedal.desktop          # 4.2-B
        ↓
PyPedal.application      # 4.2-A
        ↓
PyPedal scientific modules
```

Permanent prohibition: scientific modules importing application or
desktop. Application must not import PySide6, tkinter, or customtkinter.
Application objects must not hold Qt types. Desktop should normally
reach science through application adapters, not `pyp_*` modules.

The 4.2-A test that forbids application imports of analysis modules is
an **A-scope** restriction, not a permanent invariant. 4.2-C will add
application job adapters that call `pyp_nrm` and `pyp_metrics`. The
permanent rule is only the reverse dependency.

`pyp_app.py` may import application helpers during the CTk transition.
Application must never import `pyp_app`.

## macOS packaging spike (4.2-B)

- Spec: `tools/macos/PyPedal.spec`
- Bundle identifier: `org.pypedal.PyPedal`
- `CFBundleName`: PyPedal
- `CFBundleDisplayName`: PyPedal
- Packaged application menu identity: PyPedal
- Open is `File -> Open…` with `QKeySequence.StandardKey.Open` (Command-O on macOS). There is no Open toolbar or in-window Open button.
- Metadata page: compact, top-aligned inspector
- Signing and notarization: deferred to 4.2-D
- Finder double-click validation: deferred to 4.2-D unless separately confirmed

Development launches (`pypedal-qt`, `python -m PyPedal.desktop`) still run inside the Python interpreter. Qt metadata is PyPedal; the leftmost macOS menu may continue to show the interpreter process name until the bundled `PyPedal.app` is used.
